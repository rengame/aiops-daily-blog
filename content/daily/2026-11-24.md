公告介绍六种新的 Runbook 动作，可调用 Azure／Google Cloud API、检查资源状态并等待操作结束；可按订阅／项目、区域、资源类型和标签等筛选目标。Runbook 支持分批执行、审批暂停和错误阈值停止。复杂逻辑可使用 aws:executeScript 中的两家云 Python SDK，由 Systems Manager Cloud Connector 提供短期凭证，无需在 Runbook 保存密钥。原文示例包括停止非工作时段开发虚拟机及修复不符合安全策略的存储桶。

日期口径：本条为 **11 月 23 日发布的公告**；[Systems Manager 文档历史](https://docs.aws.amazon.com/systems-manager/latest/userguide/systems-manager-release-history.html) 对相关 API 动作记载的文档更新日为 11 月 24 日，另有 11 月 19 日的跨云 Runbook 条目。未把这些文档变更日期合并成同一功能全部首次上线的证明。

### Agent 治理

**3. OpenAI 与 Cisco 发布 Shirudo，探索经人工批准的运行时临时防护**

OpenAI／Cisco｜发布：**2026-11-24 05:20（北京时间，快照所载官方订阅 published 字段；原文页面确认 11 月 23 日）**｜首次发现：**2026-11-24 07:00:13（北京时间）**｜[原文](https://openai.com/index/introducing-shirudo)

Shirudo 是开源 Linux 运行时，通过 eBPF shield 对运行中的程序施加针对性防护，旨在永久补丁准备期间缩短风险敞口。防护部署由安全人员决定；shield 加载前验证签名，eBPF verifier 执行安全检查，并利用 TPM 支持加载／移除防护的可验证记录。官方报告在受控测试中，用 Codex 生成的输入检查阻断针对 Elasticsearch 的 Java4Shell 利用且无需重启；这不构成任意漏洞均可无损缓解的保证。更广泛的 Agent 自动调查与策略生成属于文中长期目标，未当作已交付的全自动治理系统。

### 平台工程与运维

**4. Cloudflare 用持续 DNS 探测驱动发布门控与故障发现**

Cloudflare／Doug Aaser｜发布：**2026-11-23 22:00（北京时间，快照所载官方订阅 published 字段；原文页面确认 11 月 23 日）**｜首次发现：**2026-11-24 07:00:13（北京时间）**｜[原文](https://blog.cloudflare.com/probing-dns-at-cloudflare/)

团队将 Rust 编写的 Flamingo 端到端测试框架扩展到 DNS：持续更新带时间戳的 TXT 记录，从每个数据中心查询三个权威服务器 IP 及 1.1.1.1，分别检查 90 秒和 600 秒的新鲜度阈值。由探测结果构建面向用户体验的 SLI／SLO，再用错误预算消耗判断发布健康度，支持推进或回滚；金丝雀数据中心传播延迟异常时可停止后续发布。文章源于“服务仍健康但记录数小时未发布”的故障经验，是公司工程实践介绍，不是新开源工具发布。
