## AIOps 应用

### 1. AI Gateway 上线面向 Agent 的 FinOps 会话观测

阿里云云原生社区；作者 Ruman｜发布日期：2026-11-05（日期精度）｜首次发现：2026-11-06｜[原文：AI Gateway Launches FinOps Session Observability](https://www.alibabacloud.com/blog/ai-gateway-launches-finops-session-observability-to-help-enterprises-optimize-agent-costs_603734)

**原文事实**：AI Gateway 多租户 Serverless 版新增 Agent 管理，将共享模型 API 的使用量归属到不同 Agent。统计包含 Token、错误率、Fallback 率和 P95 延迟，并可按 Session → Turn → Model Call 下钻，查看缓存命中、工具调用次数、耗时及模型调用结果。文章明确专享实例版的相关能力后续推出。

**AIOps 关联**：可把排障任务的时延与成本定位到具体处理轮次，避免只看模型 API 总用量。

### 2. ARMS Node.js 探针串联页面、Agent 与下游服务

阿里云云原生社区｜发布日期：2026-11-05（日期精度）｜首次发现：2026-11-06｜[原文：From Page Rendering to Agents](https://www.alibabacloud.com/blog/from-page-rendering-to-agents-unlocking-end-to-end-observability-for-ssr-%2B-ai-with-the-arms-node-js-instrumentation-agent_603729)

**原文事实**：文章以 Next.js、Mastra、qwen-plus、MCP Server、订单服务及 Redis 演示端到端追踪，同一 Trace ID 关联页面渲染、模型轮次、工具参数和业务调用。人工加入下游延迟后，可继续从慢工具追踪至订单 API；演示业务数据与人为注入的延迟不代表生产性能测量。首 Token 时间取决于框架和调用方式是否暴露流式数据。

**AIOps 关联**：展示如何区分模型慢、工具慢和业务依赖慢，并把 AI 观测接入传统应用排障链路。

## Agent 开发

### 3. Durable Agent：会话恢复之外，还要恢复任务执行

阿里云云原生社区｜发布日期：2026-11-05（日期精度）｜首次发现：2026-11-06｜[原文：Durable Agent Explained](https://www.alibabacloud.com/blog/durable-agent-explained-how-to-keep-an-agent-running-reliably-in-the-cloud-over-the-long-term_603735)

**原文技术内容**：文章以 AgentScope 为例，说明如何将任务阶段、工具意图、结果和等待关系保存为可恢复状态，通过原子提交保持一致。恢复从已提交的逻辑边界继续，而非重新执行整个对话。外部副作用仍依赖业务系统的幂等标识与原操作查询，持久状态本身不保证外部动作“恰好一次”。

**作者的架构讨论**：Brain–Hands 分离和更完整的 Agent as a Service 被列为基于现有 Harness 托管继续发展的方向，不能当作全部已交付能力。此文与长时运维调查、任务中断及重复操作控制直接相关。

### 4. CodeMender 0.18.0 增加工具轮次护栏与恢复可靠性修复

Google Cloud｜发布日期：2026-11-05（发布记录日期精度）｜首次发现：2026-11-06｜[官方发布记录](https://docs.cloud.google.com/release-notes/#November_05_2026)

**原文事实**：`cm verify` 增加探索性工具轮次上限，防止无界命令执行循环；CLI 在服务账号及 CI/CD 场景提供 `roles/aiplatform.agentsUser` 权限绑定诊断指引。此次还修复验证与恢复会话可靠性、Shell 兼容性及服务暂不可用时的错误反馈。

**AIOps 关联**：涉及运维工具执行预算、自动化身份配置和中断后继续执行等通用 Agent 工程问题。

## Agent 治理

### 5. Cloudflare 公布 Trusted Agent Delegation 联盟

Cloudflare；Bryan Becker｜发布日期：2026-11-05（日期精度）｜首次发现：2026-11-06｜[原文：Agents aren’t humans (but they kinda are)](https://blog.cloudflare.com/trusted-agent-delegation/)

**原文事实**：Cloudflare 宣布 Trusted Agent Delegation（TAD）联盟，计划汇集 Agent 运营者、身份验证、支付、网站和浏览器等参与方，梳理问题并推动开放协议协作。

**作者观点与方向**：文章将身份、信誉和责任归属作为代理访问网站的关键问题，讨论 WBA 请求签名、OAuth 账号身份、隐私保护信誉机制以及多级 Agent 委托。TAD 是协作倡议，文中若干机制仍在探索，不能表述为统一委托协议已经完成或普遍部署。与运维 Agent 访问外部工具时的授权主体和责任链相关。

### 6. OpenAI 发布 GPT‑6 Cyber，强化授权范围约束与访问控制

OpenAI｜发布日期：2026-11-05（日期精度）｜首次发现：2026-11-06｜[原文：GPT‑6 Cyber](https://openai.com/index/introducing-gpt-6-cyber/)

**官方发布内容**：GPT‑6 Cyber 面向漏洞研究、影响确认和修复工作，初期仅向部分获批 Daybreak Red 客户提供 API 与 Codex 访问。OpenAI 同时介绍按用户授权监测行为、默认 API IP 白名单、凭证失窃监测及针对高风险活动的限制。

**厂商评测，非独立结论**：OpenAI 报告，在其范围约束评测中，不使用部署安全提示时，99.93% 的测试未攻击范围外服务；使用该提示时为 100%。这些数字对应特定评测环境，不能理解为实际运行中绝不会越权。与安全运维 Agent 的授权边界与行为监测相关；不重复昨天已报道的 Linux 研究数量。
