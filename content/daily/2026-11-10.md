## 资讯详情

### AIOps 应用

**1. ClickHouse 托管可观测性公测，同批推出 Langfuse AI Gateway**

ClickHouse、Langfuse｜发布：**2026-11-09（仅日期）**｜首次发现：2026-11-10｜[可观测性原文](https://clickhouse.com/blog/announcing-clickhouse-observability) · [Langfuse 网关原文](https://langfuse.com/blog/introducing-gateway)

ClickHouse Observability 公测版通过托管 OTLP 端点接收日志、指标和链路，供工程师在 ClickStack 查询，也允许 Agent 通过 MCP 工具和 SQL 调查。能从自然语言生成查询、图表和调查界面的 Observability Apps 仍是私测。同批公测的 Langfuse AI Gateway 支持 OpenAI 与 Anthropic，默认记录用量、成本与元数据，提示词内容需主动开启；预算上限、供应商回退和自动路由仍在路线图上。

**2. Google Cloud Pathways 在 GKE 正式可用，提供 TPU 工作负载排障 Skill**

Google Cloud｜发布：**2026-11-09（仅日期）**｜首次发现：2026-11-10｜[工程博客](https://cloud.google.com/blog/topics/ai-infrastructure/cloud-pathways-a-distributed-ml-runtime-is-ga) · [官方发布记录](https://docs.cloud.google.com/release-notes/)

GKE 上的分布式运行时可在部分 TPU 切片故障时缩到健康切片，待替代切片加入后扩回，无需重启整个训练作业。官方记录同时列出 `pathways-workload` Skill：Agent 可读取容器日志、节点内核日志和 GKE 事件，辅助诊断失败、崩溃或停滞的 Pathways 作业。该能力面向这一类工作负载，原文没有声称提供通用自动修复。

### Agent 开发

**3. Microsoft Agent Framework 的 Durable Task 扩展正式可用**

Microsoft Apps on Azure Blog，Nick Greenfield｜发布：**2026-11-09（仅日期）**｜首次发现：2026-11-10｜[官方原文](https://techcommunity.microsoft.com/blog/appsonazureblog/durable-task-extension-for-microsoft-agent-framework-is-now-generally-available/4571100)

扩展把会话和工作流进度保存在工作进程外。工作进程重启后可恢复会话，并在重放时复用已保存的步骤结果；工作流等待人工审批或外部事件时，无需持续占用工作进程。支持 Azure Functions 和自托管的 .NET、Python 应用。

**4. Cloudflare 在 Workers 上发布实验性 Codex Harness**

Cloudflare｜发布：**2026-11-09（仅日期）**｜首次发现：2026-11-10｜[官方发布记录](https://developers.cloudflare.com/changelog/post/2026-11-09-codex-harness/)

示例把 Codex 的 Rust 回合处理逻辑适配为 WebAssembly，在 Durable Object 内运行，并保存会话、文件、事件流以及模型和工具调用结果。重启后会复用已完成步骤的结果，客户端重连可重放事件；被打断的步骤仍可能再次运行。

**5. LangGraph.js 1.7.3 修复流消费提前退出后任务仍在后台运行**

LangChain｜发布：**2026-11-10 07:58:59 北京时间**（11 月 9 日 23:58:59 UTC）｜首次发现：2026-11-10｜[官方发布说明](https://github.com/langchain-ai/langgraphjs/releases/tag/%40langchain/langgraph%401.7.3) · [官方 Release API](https://api.github.com/repos/langchain-ai/langgraphjs/releases/tags/%40langchain%2Flanggraph%401.7.3)

消费者从 `graph.stream()` 或 `graph.streamEvents()` 的异步循环提前退出，或取消读取器时，运行现在会停止。此前只在显式取消流时停止，提前退出循环会让剩余节点继续在后台运行。同版修正了子图命名空间的分段匹配，避免相似名称被误匹配。

### Agent 治理

**6. OpenAI 公开 Control Room：在推理层切断研究任务的模型输出**

OpenAI｜工程披露：**2026-11-09（仅日期）**｜首次发现：2026-11-10｜[官方原文](https://openai.com/index/control-room/)

推理请求携带作业 ID，由引擎查验该作业是否还获准生成。人工或监测系统发出停止指令后，系统拒绝后续推理；OpenAI 披露的停止上限为 35 秒，延迟来自授权缓存。服务故障时默认拒绝推理的机制已覆盖前沿模型研究负载，其他研究负载仍在部署。这里切断的是模型输出，任务进程本身可以继续运行；披露范围是内部研究基础设施。

**7. Claude Code 2.1.321 修复 MCP OAuth 凭证重定向和 Bash 权限问题**

Anthropic｜发布：**2026-11-10 03:22:30 北京时间**（11 月 9 日 19:22:30 UTC）｜首次发现：2026-11-10｜[官方发布说明](https://github.com/anthropics/claude-code/releases/tag/v2.1.321)

修复 MCP OAuth 请求在服务器跨主机重定向时可能把刷新令牌等机密发送给另一主机的问题。另修复个别只读 Bash 命令无提示地跑到沙箱外、文件写入按错误目录判断，以及 `cp` 或 `mv` 写入目录时目标文件未正确应用拒绝规则或提示的问题。

**8. LiteLLM 1.108.4 LTS 调整 Bedrock 防护策略优先级，修复团队路由**

LiteLLM｜发布：**2026-11-10 07:00:51 北京时间**（11 月 9 日 23:00:51 UTC）｜首次发现：2026-11-10｜[官方发布说明](https://github.com/BerriAI/litellm/releases/tag/v1.108.4) · [官方 Release API](https://api.github.com/repos/BerriAI/litellm/releases/tags/v1.108.4)

`/bedrock` 透传路由现在优先执行模型配置的 `guardrailConfig`，调用方传入的配置不能覆盖它。同版修复团队密钥被代理全局通配部署接管、未进入该团队自带密钥部署的问题。这与上一期收录的开发版提示词留存功能是不同的版本和改动。

### 平台工程与运维

**9. GKE Gateway 支持按 SNI 路由并透传 TLS**

Google Cloud｜发布记录：**2026-11-09（仅日期）**｜首次发现：2026-11-10｜[GKE 官方发布记录](https://docs.cloud.google.com/kubernetes-engine/docs/release-notes)

`TLSRoute` 可根据 SNI 把流量转发给 Kubernetes Service，GKE Gateway 负载均衡器无需终止 TLS，后端可自行处理。该能力适用于文档所列的单集群和多集群 GatewayClass，需要 Gateway API 标准通道 1.5.0 及以上的 CRD；对应 CRD 随 GKE 1.35.2-gke.1842000 及以上版本安装。

**10. 阿里云云效分享代码评审如何保存仓库规则**

阿里云原生社区｜技术文章发布：**2026-11-09（仅日期）**｜首次发现：2026-11-10｜[官方原文](https://www.alibabacloud.com/blog/alibaba-cloud-devops-intelligent-code-review-keeping-team-rules-in-effect_603749)

Review Memory 将评审里解释过的兼容性约束、团队约定等保存成仓库规则，后续相似变更可复用。管理员可设定候选记忆先审批再生效，也能编辑、停用或删除。文中误报改善数据来自云效团队自建的测试集，不能外推到其他仓库；这是技术实践文章，未把它当作功能首次上线公告。
