## 资讯详情

### Agent 开发

#### 1. LangGraph 1.2.22 修复独立线程子图的流式事件交付

LangChain / LangGraph｜版本发布：**2026-11-14 09:43:55**（01:43:55 UTC，GitHub Releases API）｜首次发现：2026-11-15｜[版本说明](https://github.com/langchain-ai/langgraph/releases/tag/1.2.22) · [子图修复](https://github.com/langchain-ai/langgraph/pull/9698) · [PostgreSQL checkpoint 3.2.1](https://github.com/langchain-ai/langgraph/releases/tag/checkpointpostgres%3D%3D3.2.1)

当节点在独立线程中调用子图时，父调用开启子图流式订阅也可能收不到子图消息或工具事件。新版修复了这条事件交付路径。同批发布还减少了 checkpoint 的部分读取开销，例如 PostgreSQL 后端用连接池时绕开一处异步锁。多个关联包合计为一条资讯。

### Agent 治理

#### 2. LiteLLM 1.108.9 LTS 增加 Vertex AI 调用方成本归因

LiteLLM 项目｜版本发布：**2026-11-15 06:00:02**（11 月 14 日 22:00:02 UTC，GitHub Releases API）｜首次发现：2026-11-15｜[版本说明](https://github.com/BerriAI/litellm/releases/tag/v1.108.9) · [Vertex 标签变更](https://github.com/BerriAI/litellm/pull/51786)

LTS 分支新增可选的 Vertex 调用方身份标签，便于在 Cloud Billing 中按密钥、团队、组织和项目归因。该版也修复了 Chat 转 Responses 时的缓存断点处理，以及混合推理与答案内容的保留问题。与上期 1.108.8 的 MCP 登录修复是不同版本与变更。

#### 3. LiteLLM 候选版支持从 CLI 绑定用户自己的 GitHub Copilot 凭证

LiteLLM 项目｜**候选版**发布：**2026-11-15 07:46:31**（11 月 14 日 23:46:31 UTC，GitHub Releases API）｜首次发现：2026-11-15｜[官方发布 API](https://api.github.com/repos/BerriAI/litellm/releases/tags/v1.107.0-rc.4) · [回移变更](https://github.com/BerriAI/litellm/pull/51771) · [实现说明](https://github.com/BerriAI/litellm/pull/50863)

1.107.0-rc.4 将按用户绑定 GitHub Copilot 凭证的功能回移到候选分支。管理员先配置按用户的凭证；开发者可从 CLI 发起设备授权，并在 GitHub 完成批准，无需进入 LiteLLM 管理界面。本项不属于 1.108.9 LTS。

### 平台工程与运维

#### 4. Temporal Python SDK 1.36.1 调整工作流激活的默认行为

Temporal｜版本发布：**2026-11-14 10:23:49**（02:23:49 UTC，GitHub Releases API）｜首次发现：2026-11-15｜[官方版本说明](https://github.com/temporalio/sdk-python/releases/tag/1.36.1)

单批处理工作流激活默认关闭，未记录逻辑标志 2 的工作流继续沿用原有信号、条件等待和取消行为；历史中已有标志 2 的工作流继续按单批模式处理。对长期运行的自动化任务，这一区别关系到升级前后如何延续已有执行历史。

#### 5. Cloudflare 通报 R2 和 Tiered Cache 错误率上升

Cloudflare｜**首条公开通报：2026-11-14 13:30:35**（05:30:35 UTC，状态 API）｜首次发现：2026-11-15｜[官方事件全文](https://www.cloudflarestatus.com/incidents/a643zcsfc71q) · [官方状态 API](https://www.cloudflarestatus.com/api/v2/incidents.json)

厂商称，自北京时间 13:00 起，多座数据中心之间的网络连接问题导致少量请求失败，芝加哥和纽瓦克错误率最高。R2 可能返回 HTTP 500，Tiered Cache 可能返回 520、522 或 524；14:45 UTC+8 标记解决。这是故障通报，不是功能发布。稍后西北美 R2 桶错误另有[独立事件页](https://www.cloudflarestatus.com/incidents/dpao7idy3zei)，厂商未说明两者存在关联。
